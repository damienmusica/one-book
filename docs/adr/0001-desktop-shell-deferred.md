# ADR 0001 — 데스크톱 셸 유보, 셸-독립 불변식 채택

- 상태: 채택 (2026-08-16)
- 관련 오더: 외부 리뷰 스펙 2건 (Electron 우선 검토안 → Tauri 재검토 요청)

## 결정

**지금은 어떤 데스크톱 셸도 도입하지 않는다.** 정적 웹 번들(`dist/`)이 유일한 소비자이며,
아래의 셸-독립 불변식을 코드베이스의 규칙으로 채택한다. Tauri 2 대 Electron 판정은
실제 배포 필요가 생기고 3개 플랫폼 실측이 가능해질 때, 본 문서의 평가 프로토콜로 수행한다.

## 맥락

이 오더의 실제 목적은 "외부 리뷰어(GPT sol max)와의 공동 검토"다. 그에 필요한 것은
재현 가능한 캡처·지표·상태 덤프이지 데스크톱 배포물이 아니다. 그 필요는
QA 캡처 하네스(`qa/`, `docs/qa-harness.md`)가 셸 없이 충족한다.

앱은 이미 구조적으로 셸-독립이다:

- 순수 정적 번들 — 상대 base(`./`) + 해시 라우팅이라 어떤 정적 경로에서도 동작.
- 외부 요청 0 — QA 하네스가 모든 비-localhost 요청을 차단한 상태로 전 씬을 통과
  (오프라인 실행 가능성의 기계 증명, `console.json`의 `blockedExternalRequests: 0`).
- 네이티브 모듈 0, Node API 의존 0.

"셸은 교체 가능해야 한다"의 가장 강한 형태는 **교체할 셸 코드가 없는 상태**이고,
현재가 그 상태다. 지금 셸을 고르는 것은 이 성질을 약화시키는 결정이며, 단일 macOS
머신에서의 "측정"은 OS WebView 복권을 반영하지 못하는 위장 측정이 된다.

## 셸-독립 불변식 (오늘부터 유효)

1. 지식 데이터(`data/`), 3D 엔진(`src/globe/`), 상호작용 모델(`src/state/`),
   QA 씬(`qa/scenes.mjs`)은 셸 API를 일절 참조하지 않는다.
2. 앱과 하네스의 대화 창구는 `window.__lpQA`(읽기 전용 계측)뿐이다.
3. 오프라인 실행 계약은 "임의의 정적 서버로 `dist/` 서빙"이며, QA의 외부 요청
   차단이 이를 회귀 검증한다.

## 미래 평가 프로토콜 (Tauri 2 vs Electron)

전제조건: (a) 실제 배포 필요의 확정, (b) Windows·macOS·Linux 3플랫폼 실측 가능,
(c) 서명·배포 절차 합의.

대표 씬은 QA 하네스의 기존 씬을 그대로 쓴다 — overview(행성 전체),
kafka(밀집 성좌+방향 애니메이션), works-cities(작품 도시·지형),
timeline/coordinate-transition(필터·좌표 전환), 그리고 결정적 캡처 신뢰성 자체.

측정 항목: 인스톨러/설치 용량, 콜드 스타트, 유휴/피크 메모리, p95 프레임 타임,
WebGL 호환성, 플랫폼 간 텍스트·라벨 일관성, 자동 캡처 신뢰성, 접근성·키보드,
보안 표면과 유지비.

판정 규칙: **기능 동등·3D 안정·결정적 캡처가 3플랫폼에서 성립하면 Tauri 우선.**
Electron은 번들 Chromium의 이점(렌더링 일관성, WebGL, 자동화)이 실측으로
필요하다고 증명될 때만 선택한다.

오늘 알려진 트레이드오프 (실측 전 가설로 기록):

- Tauri 2: 설치 용량·메모리 우위 / OS WebView 편차(특히 Linux WebKitGTK의 WebGL
  신뢰성), CDP 부재로 자동화·영상 캡처 경로 미성숙(tauri-driver).
- Electron: 3플랫폼 동일 렌더링·Playwright/CDP 일급 지원 / 용량·메모리·Chromium
  패치 케이던스 유지비.

## 오늘 확보된 기준선 (셸 비교가 아님)

동일 씬·동일 뷰포트(1920×1080@1) 기준, macOS(M4 Pro):

- 하드웨어(ANGLE Metal): avgFps 55.2, p50 16.7ms, p95 18.1ms
- SwiftShader(소프트웨어): avgFps ~17 — 기능·결정성 검증 전용, 성능 판정 금지

이 수치는 씬의 무게에 대한 기준선일 뿐, 어떤 셸의 성능도 대변하지 않는다.
