2026-08-24, CPO 지시: "버티컬 슬라이스 완성 코앞이니까 물량작업 같은 건 Opus 5가
알아서 잘 이어나갈 수 있게 가이드 줘라. 너무 상세한 가이드로 창의력 해치지는
않는 선에서."

이 문서는 **레시피가 아니라 지도**다. 완성의 정의와 불변 조건만 고정하고,
경로는 이어받는 세션의 몫이다. 정본은 언제나 문서다 — 이 가이드와 충돌하면
`docs/universe-thesis.md`(구조) · `docs/design-thesis.md`(시각·헌법) ·
`docs/r11-observation-protocol.md`(관찰) · AGENTS.md(작업 규율)가 이긴다.

## 지금 어디까지 왔나

카프카 버티컬 슬라이스 = **서가 회랑**(테제 §⑦, R12-c). 관계 인과성(방향
글리프·화살촉·"왜" 캡션·앵커), 작품 세계(여는 문장·판본·유고), 서명 파도(62),
선 다이어트, 표면 관측창 투영, 당김, 이륙까지 구현·계약 완료. R12-d 가
**손안의 성계**(테제 §⑫)를 더했다: 좁은 화면 배치(서랍·시트·누운 화면의 옆
시트), 세로 프레임의 회랑 자세, 손가락의 두 탭 문법, 그리고 그것을 재는
`verify-mobile` 레인 32건 + 변이 11건. 그 뒤는 **내부 심사(시각 판정 + 자체
적대 검토) → 3인 욕망 테스트(프로토콜 §7) → 통합 직전 CPO 최종 15분**의
게이트 사다리다(게이트 축소, CPO 2026-08-25).

R12-e 는 외부 검토가 짚은 자리를 닫았다(테제 §⑬): 오탭 · 이름표 상자 검사 ·
도착 카드 초기화 · 범례 핀 · 리사이즈 · 같은 칸 관통 · 카드 행 지목. 계약은
데스크톱 335 · 손안 52, 변이 112(브라우저+손안 73 전부 KILLED).

**손안의 교훈 하나는 물량 트랙에도 적용된다**: 넓은 화면 계약 316건이 전부
초록인 채로 전화기에서는 아무것도 되지 않았다. 새 계약을 달 때 "무엇을 재지
않고 있는가"를 먼저 묻는다 — 상태 단언은 화면을 보지 않는다.

## 물량 트랙 — 완성의 정의와 본보기

각 트랙은 **본보기 하나가 이미 레포에 있다.** 새로 발명하지 말고 본보기의
수준을 복제하라. 속도를 위해 수준을 낮추는 것은 완성이 아니다.

1. **작품 세계 확장** — 다음 대상: 소세키 6작품 · 타고르 6작품(착륙 가능 작가
   먼저). 본보기: 카프카 5작품의 `world` 필드(`data/works/early-west-a.json`)와
   출처 묶음(`data/sources/kafka-world.json`). 완성 = 여는 문장을 **실제로 연
   페이지에서 축자 확인**(PD 원문 — Wikisource·Aozora Bunko 등, URL·accessedAt
   기록), 한국어는 자체 번역으로 표시, 판본·유고는 출처와 함께, 스키마·검증
   통과. 기존 한국어 번역서의 문장을 가져오는 것은 금지다(저작물).
2. **관계 앵커 큐레이션** — 카프카 10행이 본보기(`data/relations/*.json` 의
   `anchors`). 완성 = 나머지 관계 중 **요약문이 이미 지목하는** 책·연도만 앵커로
   승격(새 조사 0, 요약에 없는 사실 금지), 검증 통과(당사자의 실재 작품만).
   요약이 아무것도 지목하지 않으면 앵커를 만들지 않는다 — 실이 이름에 닿는
   것도 정직한 독해다.
3. **실물 자산 파도** — 본보기: 서명 파도(`art-r10/stage-signatures.mjs` →
   `build-art-assets.py`, 원장 `docs/art-direction-r10.md`). 남은 것: 보류 6건의
   인간 재검(울프 크롭·CC BY-SA 판단), P18 기록 사진 파도(99인 가용 — 파일별
   권리 확인이 병목), 육필 지각 파도. 완성 = 파일마다 프로비넌스 행, 정책 보류
   (생존 작가·공유동일조건)는 코드가 아니라 기록으로 남김, 출하 행성 앱의 자산
   집합 불변(매니페스트 버킷 분리 원칙 유지), 관련 계약 통과. 수집 우선순위는
   편집 균형(지역·언어 공백 우선, 정전 순 금지 — 테제 §⑤).
4. **다국어 정합** — `node-translations` 계열과 새 표면 문자열(회랑 각인·시트
   라벨)의 en 로케일 정합은 아직 손대지 않았다. 기존 로케일 체계 안의 정합은
   자체 판단으로 진행한다(새 로케일 추가만 범위 확장이다).

## 불변 — 어기면 되돌린다

- 하드 제약 전부(AGENTS.md): 로그인·DB·UGC·스크레이핑·비밀키·클라우드 LLM
  의존·광고·결제·추적 없음.
- **지어내지 않는다**: 상상 얼굴·지어낸 인장·없는 표지·출처 없는 문장 금지.
  없는 것은 없다고 적는 것이 이 제품의 문법이다.
- 한 채널 한 의미(테제 §③). **게이트 축소(CPO, 2026-08-25): 자체 해결 가능한
  것은 전부 자체 해결한다.** CPO 에게 가는 것은 넷뿐 — 사람·일정 제공,
  정체성·하드 제약급 정책 변경, 되돌리기 힘든 대외 행위, 통합 직전 최종 15분.
  문법·스키마·프로토콜 개정과 수집·연출 판단은 CTO 가 내리고 결정 로그에
  사후 기록한다. 판단 근거는 언제나 실측이다.
- 측정 없이 주장하지 않는다: 게이트 수치는 실행 결과만 적는다. 계약을 새로
  달면 변이로 이빨을 확인한다(`universe:mutation-sweep`).
- 스윕이 도는 트리는 잠긴다(nohup 로 띄우고 끝까지; 죽일 땐 SIGINT만).
- 커밋은 논리 단위로, 명시 경로만 스테이징(`git add -A` 금지). PR 은 그린 확인
  후 머지("no checks reported"는 그린이 아니다).
- 생성과 QC 는 컨텍스트를 분리한다(모델 라우팅: 생성 배치 = Sonnet, 심사 =
  가용 최강 티어).

## 게이트 명령

```bash
npm run typecheck && npm run validate:data && npm test
node art-r11/verify-journey.mjs        # 넓은 화면 여정 계약 (dist 빌드 후)
npm run universe:mobile                # 손안의 계약 — 390×664, 손가락 입력
npm run universe:reproduce             # 한 명령 전체 게이트 + 리포트
npm run universe:mutation-sweep        # 계약의 이빨 측정 (트리 잠금)
```

새 화면 문법을 더하면 **넓은 화면과 손안 양쪽에** 계약을 단다. 한쪽만 달면
다른 쪽이 조용히 깨진 채로 게이트를 통과한다 — 그것이 R12-d 의 출발점이었다.

## 창의가 허용되는 곳

회랑의 연출 상수(빛·안개·잉크·카메라 미세값), 시트·각인의 문장, 자산 파도의
순서와 묶음, 조사 경로 — 전부 네 판단이다. 단 **화면 문법의 의미**(무엇이
무엇을 뜻하는가)를 바꾸는 순간 그것은 창의가 아니라 개정이고, 개정은 실측
(프레임·계약·변이)을 근거로 CTO 가 판정해 결정 로그에 남긴다. 판단이 막히면
실측을 만들어라 — 이 레포의 모든 좋은 결정
뒤에는 스크린샷·계약·변이 중 하나가 있다.
