# 문학의 행성 (Literary Planet) — 정제된 프로덕트 브리프 v1

**계보:** Noosphere 결정 (86)이 예약한 자매품 옵션 "Booksphere"(예술로서의 문학)의 첫 프로토타입.
vault `reference/booksphere-literature-boundary-thesis.md`가 상류 근거다. 이 앱은 Noosphere가
"관념의 역사" 렌즈로 다루는 문학을, **예술의 그물망**(영향·친연성·운동·번역) 렌즈로 다룬다.
같은 인물(예: 카프카)이 두 구체에 다른 렌즈로 존재할 수 있다.

**지위:** 사이드프로젝트 · 프로토타입. Noosphere 본체의 `/data`, `foundry/`, 거버넌스 문서와
완전히 분리된 자립 패키지(`literary-planet/`)로 존재한다. 본체 차터에 대한 스코프 포인터 추가는
CPO 게이트(결정 (91) stop-set: 거버넌스 변경)이므로 이 프로토타입은 수행하지 않는다.

## 상속하는 하드 제약 (Noosphere 부트스트랩 규율 미러 — 결정 (86) §4)

- 로그인·계정·인증 없음. 관리 UI 없음. DB 없음 — JSON 데이터 파일만.
- UGC·댓글·공개 편집 없음. 스크래핑·크롤링 없음. 광고·결제 없음. 사용자 추적 없음.
- 레포·환경에 시크릿 없음.
- **LLM 경계:** LLM은 유지관리자가 대화형으로만 사용(데이터 초안 생성·QC 보조).
  빌드·런타임·CI·레포 도구는 LLM을 요구하지 않는다. 커밋된 JSON이 산출물이다.
- 근거 없는 관계·가짜 출처 금지. 직접 영향의 근거가 없으면 반드시 `editorial_inference`
  (편집적 친연성)로 강등 표기한다.
- 저작권 작품의 긴 인용 없음 — 모든 해설은 직접 작성한 요약.

## Noosphere와 다른 점 (의도된 차이)

| | Noosphere 본체 | 문학의 행성 |
|---|---|---|
| 우선순위 | 데이터 파운데이션(UI 아직 없음) | **탐험 UI가 곧 제품** (3D 지구본) |
| 택소노미 | 13-관계 지식 택소노미 | 문학 고유 6-관계 택소노미 (직접영향·번역·사사·대화·친연·대조) |
| 큐레이션 게이트 | Foundry 결정파일 + apply-batch | 경량: `reviewStatus` 사다리 + `evidenceLevel` + 기계 검증 |
| 좌표 | 없음 | 이중 구면 좌표 (문학적 친연성 / 실제 지리) |

주의: "3D globe 아직 없음"은 **본체의** 제약이다. 이 사이드프로젝트가 지구본 기술의
실험장 역할을 하며, 검증된 패턴은 미래 본체 globe의 리스크를 낮춘다.

## 마스터 프롬프트 대비 정제 결정 (CTO 재량)

유지: 20세기 중심 5개 시대층(의도적 중첩) · 장르층 · 이중 좌표계 · LOD · 검색/필터/연대
슬라이더/URL 상태 · 상세 패널의 전체 편집 필드 · 근거 수준 3분류 · 작가 100명 + 관계 250개 ·
가이드 투어 · 비교 · 접근성/reduced-motion · 결정적 좌표 동결 · 방법론 공개.

조정:

1. **필수 앵커 목록 = 정확히 100명** — 마스터 프롬프트의 4개 층 목록(12+34+37+17)이 초기
   코퍼스 전체다. 확장 목록은 v2 슬레이트로 이월.
2. **출처 규율 > 출처 개수** — 검증 안 된 딥 URL을 기입하느니 기관·문헌명 인용만 기록한다.
   URL은 검증된 도메인 수준만. `verified` 지위는 v1에서 부여하지 않는다(외부 검증 절차 미구축).
   기계 검증 + Wikidata 생몰년 교차확인 + 오케스트레이터 정독 샘플링을 통과한 배치가 `reviewed`.
3. **작품 위성 시각화**(선택 작가 주변 궤도)는 프롬프트상 선택 사항 — v1은 패널 내 목록으로
   대체하고 v2 후보로 기록.
4. **지리 모드 해안선 지도는 v1 제외** — 경위선 격자 + 지역 라벨로 가독성 확보. 외부 지형
   데이터 의존을 늦춘다.
5. **UI 자동 테스트는 정직한 경계로** — 데이터 불변식·레이아웃 결정성·URL·검색·그래프·컴포넌트는
   vitest로 자동화, WebGL 상호작용(드래그·줌·픽킹)은 실브라우저 수동 검증으로 확인하고 문서화.
   jsdom으로 WebGL을 흉내 내는 가짜 테스트를 만들지 않는다.
6. **배포는 하지 않는다** — 이 레포에 기존 배포 경로가 없다. 로컬 프로덕션 빌드까지 완성.
7. **라우팅은 해시 기반** — 정적 호스팅 어디서나 리라이트 규칙 없이 동작(URL 공유 요건 충족).
8. 스키마에 `gender` 필드 추가(커버리지 보고서의 젠더 분포 공개 요건).

## 완료 조건

마스터 프롬프트 §18의 12개 질문을 그대로 채택한다. 단 "테스트 통과"는 위 5번의 정직한 경계
안에서의 자동 테스트 + 실브라우저 검증 기록을 의미한다.
